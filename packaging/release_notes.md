Governed legal case preparation: it takes the papers in a dispute, establishes what is said and by whom, finds and checks the law, and assembles a source-linked analysis for a named human to review. It renders no verdict.

**A high-risk AI system under the EU AI Act (Article 6(2) and Annex III, point 8(a)). It has not been conformity-assessed or validated on real matters, and it is not legal advice.** Read the [documentation](https://github.com/ShadowESC95/ELI_Legal/blob/@TAG@/docs/README.md), starting with the legal overview, before using it on a matter.

## New in this version

- **Each kind of information kept for its own period.** A closed case's content is no longer one block with one date. Its **papers** (originals, text, search index), its **analysis**, its **reports**, its **evidence packs** and its **decision record** (runs, reviews, approvals, releases, holds, incidents) each have their own period, chosen at set-up and in Compliance → OA-09, with the reasons for the suggestions given: six years for papers (professional rules and limitation periods), ten for evidence packs (EU AI Act Art. 18) and for the decision record (Arts. 12, 14, 19), the analysis and reports as long as the papers unless set otherwise, the audit trail at least six months. Each kind is archived under its own key and retired on its own day by the routine checks (its key destroyed, or it is deleted), unless a preservation hold keeps it; the decision record goes last, only once nothing it accounts for is left, and cannot be set shorter than what it accounts for. **File → Closed cases** shows each kind's state and end date; reopening says what is no longer there. Controls DG-01.41, DG-01.43.
- **Every case file encrypted on disk.** The original documents, every version of the report, the copies staged for release and the evidence packs ELI Legal keeps are sealed with AES-256-GCM under a key per case and kind, each file bound to its case and place: open or closed, a copy of the data folder without the secrets folder reads as nothing. Destroying a kind's key makes every copy unreadable, backups included. What is handed over on purpose (an evidence pack written to a folder you choose or downloaded, a report saved as PDF or Word) is plain where you put it, and recorded. Files from earlier versions are sealed, and 0.8.15's archives split by kind, the first time 0.8.16 starts. Control DG-01.42.
- **The databases are encrypted.** The working database (matters, documents' text, the search index, findings) and the audit ledger are encrypted with SQLCipher (AES-256, every page and the write-ahead log) under a key made on first start, kept in the secrets folder and, on Windows, protected for the account running ELI Legal. A database an earlier version left plain is converted at the next start: the encrypted copy is checked (every row, the search index, the ledger's whole chain) before it replaces the plain one, which is then overwritten. A wrong or missing key is refused, never answered with an empty database. **Close ELI Legal (and its server) before starting 0.8.16 for the first time**, so the conversion has the files to itself. **Losing the key loses the databases:** save it once with `eli-legal database-key --out <file>` and keep it apart from the backups of `data/`. Control DG-01.44.
- **What others do shows on your screen.** The desktop and the server share one set of live data on the main machine (the server started from Settings → System runs inside the desktop itself). Now, when someone else acts on the case you have open, in the browser or on another machine, the stage bar, the header and the page in front of you update within ten seconds without pressing F5, if it is a page that only shows the case (Home, Progress, Who does each step, Findings, Review and approve, Record of actions, Released to me, Documents); never while a dialog is open or work is running, so nothing being typed is lost.

**Also new, from 0.8.15** (built but not published: its Windows checks failed on a type check, fixed here):

- **Closed cases: off the list, not lost, and reopened.** Closing a matter now asks what happens to its content: **archived** (the default: its documents, text, findings and reports sealed, encrypted with AES-256-GCM, each kind under a key of its own, proved to read back, then removed from the working database, overwritten), **kept**, or **deleted** for good. A closed matter leaves the case list; **File → Closed cases** lists them all, with where each one's content is and until when it is kept, and can view one, **reopen** it (its archive checked fingerprint by fingerprint and restored, its team given access again, anyone suspended since left out and named), archive it later, or delete it. When its retention period ends the routine checks destroy each kind's archive key, so no copy can be read again, unless a preservation hold keeps it. Control DG-01.41.
- **No crash when closing a matter.** Choosing to delete a matter's content at closing crashed the desktop: the dialog's tick box was gone before it was read. Fixed for the ten decisions that ask a question beside their reasons (closing, preservation holds, restarts, checks, how a run ends, incidents and others), and tested with the real dialog.
- **Processor, memory and graphics use, on any machine.** The status bar shows how busy the machine is and how much of it ELI Legal uses, with every graphics processor's use and memory: on Windows any maker's (from DXGI and Windows' own counters, in any language of Windows), on macOS Apple silicon's unified memory and Intel Macs' graphics, on Linux NVIDIA, AMD (its own memory, or the system memory an APU shares), Intel, Arm boards, Jetson and Snapdragon. Shared and unified memory are named as such; what a machine does not report is left out. View → Show or hide. Controls MO-01.10.
- **Nobody checks their own work.** By default the person who started a run can no longer approve, return or reject its report: another named reviewer decides, and the matter's lead is told when one is needed. The desktop disables the decision for the person who ran it and says why. An organisation's policy file may allow it (a sole practitioner); every run records which policy applied. The person who proposes a deployment authorisation can no longer sign it: two other people sign. Policy version 0.5.0.
- **How long the record is kept is chosen at set-up.** The first-run window and `eli-legal init` ask how long to keep the audit trail (at least six months), a closed matter's documents, and how long an open matter may sit idle before it is reported; unattended, `init` takes `--audit-days`, `--closed-matter-days` and `--inactive-matter-days`, or `--retention-later` on purpose. A matter can keep its content for its own period (the new-matter wizard, `--retention-days`). The routine checks delete on time and report idle matters, and `eli-legal checks timer --install` runs them daily from the operating system's scheduler, so a period ends on time even when ELI Legal is closed.
- **Deleted means gone from the files.** Deleted database rows are overwritten; after a matter's content is deleted the database is rebuilt and its log emptied, and files ELI Legal deletes are overwritten first. The deletion receipt says so.
- **Case files are private on disk.** Folders 0700, databases 0600, originals read-only; what an earlier version left readable by others is tightened when ELI Legal starts.
- **Security policy and an audited release.** [SECURITY.md](https://github.com/ShadowESC95/ELI_Legal/blob/@TAG@/SECURITY.md) says how to report a weakness privately and what happens next; `eli-legal doctor` shows where. Each release now carries a CycloneDX bill of materials (`ELI_Legal-…-sbom.cdx.json`) and is built only if a known-vulnerability audit of what it ships passes, any exception recorded with its reason. pypdf is now at least 6.21.4.

## Still to know

- Benchmarks measure retrieval and linking against answers fixed in advance on public legislation. They are not a measure of accuracy on real matters, which has not been done. Before a real matter is relied on, an authorisation needs that evaluation as evidence, and a lawyer's validation of the legal-system packs.
- Case law's later treatment (overruled, distinguished) needs a licensed citator source; the open databases ELI Legal reads do not supply it, so a case's standing goes to a person.
- Tesseract and Poppler are not included in the installers: install Tesseract for photographs and scans to be read, and Poppler as well for scanned PDF pages.
- The keys are kept in the secrets folder on the same machine: they protect a copy of the data folder, a backup or a disk image made without it, not the machine itself. Keep the machine on an encrypted disk (BitLocker, FileVault, LUKS) and back up the secrets folder with the data folder, stored apart: a lost key is lost data.
- A repeal of part of a subsection, or of words within it, is not detected; a consolidated EU text is documentation, not the authentic text.

| Debian, Ubuntu | `eli-legal_…_amd64.deb`: `sudo apt install ./<file>` |

Every one of them includes the desktop application, the server with its browser application (`eli-legal serve`), and the command line. Your matters, the audit ledger and its key are kept in your user data folder, apart from the program; removing the program never removes them.

## Before you run it

- **These builds are not signed.** Windows SmartScreen and macOS Gatekeeper will warn. Check your download against `SHA256SUMS` first: `sha256sum -c SHA256SUMS --ignore-missing`.
- **An installed copy needs a licence key:** one for ELI Legal, or an ELI v3 key that includes it. The terms are in `LICENSE`, shipped with every build.
- The Linux builds are made on Ubuntu 22.04 and run there and on anything newer. The graphics card is used on Ubuntu 24.04, Debian 13, Fedora 39 or newer (C library 2.38), which the graphics packs need; on an older system a model runs on the processor.

## What was tested

- **Linux:** the installer was installed, run through the synthetic dispute from filing to an approved, released report, and uninstalled; the AppImage ran the same dispute, and its desktop window was opened on a virtual display and typed into.
- **Windows:** the program ran the synthetic dispute; the setup program was installed silently, started and uninstalled. The desktop application was not opened by a person.
- **macOS (Intel and Apple silicon):** the program ran the synthetic dispute. The disk images were not opened by a person.
- The test suite (desktop application, server, browser application, security, the whole lifecycle, the benchmarks) passes on Linux, Windows and macOS.
- **New in this version:** images read by OCR (and an image read with too little confidence, or not at all, held), notifications reaching only those who can act and going when the work is done, two people signed in to the server each seeing their own, and the resized desktop window are tested.
